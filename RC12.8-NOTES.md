# RC12.8 — Directional ports, split & merge flows

## What changed
- Journey nodes now have a strict visual connection grammar:
  - **Incoming:** 3 ports on the top + 2 ports on the left.
  - **Outgoing:** 3 ports on the bottom + 2 ports on the right.
- A single port can carry multiple edges. This supports both:
  - one flow splitting into multiple branches;
  - multiple branches merging into one component.
- New and imported connections are normalized to directional handles automatically.
- Legacy RC12.7-and-earlier handle IDs are translated to the closest valid directional port.
- Print/PDF now respects the exact top/left/bottom/right port positions more closely.
- The portable `.fjs`, `.jstemplate` and `.jsjourney` schemas remain unchanged.

## Journey-authoring rule
Future generated journeys should use the directional port model explicitly: arrows enter at top/left and leave at bottom/right. Branching and merging should use shared or adjacent ports depending on the cleanest visual route.
